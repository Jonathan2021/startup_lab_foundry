RETURN TO YOUR WORK

Using Foundry

Keep the question, evidence and next action together. Start with an idea or bring in a project that already exists.

Keep decisions current

Use Today to find pending results and changes across ventures. Inside a venture, Now lets you record a change, prepare context for your agent and review findings. The decision map connects current work to purpose and possible outcomes. Inspect missing evidence, preview exact work effects and accept a result with rationale. A stale result remains readable and needs reconciliation. Read the agent workflow.

Start or join

Add an idea when you have a problem to explore. Open its page and choose “Open venture investigation” to retain experiments and decisions. Join an existing project when code or prior work already exists. Record the repository reference, maturity, decisions, uncertainty and next test. For example, Coopain can have a prototype while its payer remains unknown. A checkpoint preserves the earlier work; it does not validate a business.

Request an initial review

A fresh idea starts unscored. Choose Request initial review to save a task, or promote it to a venture to queue that venture's manual intake. The label says Queued for manual agent review. Copy or download its handoff, start an agent session and claim the exact task. Completion retains attributed research, justified factors, unknowns and the next owner/action. It does not run an unattended worker or authorize outreach.

Repeated promotion opens the same venture. Creating a separate venture with an explicit distinct ID keeps its work and assessments independent. A copied source baseline remains pinned; it is not a new validation result.

What the records mean

An idea describes a possible opportunity. A venture is its working investigation or project. An assumption is something that must be true. An experiment tests it against criteria chosen first. Evidence is an attributed observation with limits. An assessment interprets that evidence. A decision says what you will do and why. An artifact points to a report, file or other output.

A step is a bounded operation. “Succeeded” means it ran, not that the venture passed. Readiness and research briefs run locally. Agent requests produce a handoff and remain blocked until handled. Browse steps.

Read and update scores

Original workbook shows imported judgments and reported confidence. It retains all 12 factors, the source formula, source rank and unvalidated monthly revenue ranges. Current reviewed is the default. A venture has its own assessment history. A starting score says “Source baseline” and identifies the original idea assessment; later idea edits do not change that saved baseline.

Priority uses revenue, profitability, MVP speed, founder fit, go-to-market, moat, problem intensity and retention, less legal, capital, network and competition penalties. Higher penalty scores mean more risk. Scores are provisional attraction, not a probability of success or permission to build. Unknown factors keep the total unknown; coverage shows how many were supplied.

Open a venture → Scores → Append a reviewed assessment. Supply only the factors you can justify, a reviewer and evidence rationale. New assessments preserve earlier ones and leave the idea's scores intact. Changed weights require a new scorecard version through the CLI. A high priority and a human-input hold can coexist.

State and next action

Investigation stage identifies the question: intake, triage, comparison, problem, solution or business validation. Product maturity says what exists: unknown, concept, prototype, MVP, pilot or operating. Disposition is the investment choice: pursue, hold, dropped, internal only or use existing. Venture lifecycle remains separate.

Next work shows whether the linked task is ready, in progress or blocked by human input, access or setup. Without an assigned task it says “not scheduled”. There is no invented validation percentage. Open Current review → Update review, choose each dimension, explain the decision and give the next action. Reopening a held or dropped item appends a new review; the earlier reason remains in history.

Find the work that matters

On Ideas or Ventures, combine search, disposition, investigation stage, maturity and next-work filters. Choose Original workbook or Current reviewed, a factor and sort order. Unknown scores sort last in either direction; tied rows have stable IDs. Pagination keeps every filter. “Needs my input” finds human-input blockers. Try Coopain as a prototype, or founder fit. Clear filters to restore all rows, including held/dropped ideas.

Answer and review

Open the question from a venture's next action, or use Needs you in the Inbox. Save your answer on the question page. It then appears under Awaiting review. You can also edit the response in its registered file: preview changes in the Inbox and explicitly synchronize them. A correction preserves the earlier answer. If a file and a saved answer diverge, choose which one should be reviewed.

Copy or download the question's agent handoff to start a manual agent session. The reviewer claims the exact answer, records an interpretation and outcome, and updates only the affected work. Copying and synchronization queue work; they do not start an agent. Reviewed means the answer was assessed, not that the venture is validated. Deferred questions remain visible under Holds and do not ask for the same input again.

Review a fusion proposal

Proposals shows the source ideas and ventures, included and deferred scope, alternatives and proposed work changes. Read the exact revision before accepting, editing or rejecting it with a reason. Acceptance creates a new idea and venture, preserves both sources and links their history. A later reversal also preserves the records and needs a treatment for any downstream work. The volleyball proposal is pending until you decide.

Use a venture workspace

The header keeps the venture ID, score and next action visible. Work, Evidence, Decisions, History and Scores show records for that venture. Settings lets you enable Software and Outreach when useful; hiding a module keeps its records. Software shows a linked repository/checkpoint and reported test status. Missing security evidence remains unassessed. Business metrics distinguish reported actuals from estimates and leave unknown values blank.

Draft, export and record

Open a venture → Create outreach draft, or browse drafts. Record the purpose, explicit To/Cc/Bcc, subject, body, language and tone. A recipient may stay unresolved. Edits create a new content revision; earlier text is retained. Choose registered attachments explicitly. Export text to copy into your mail tool; .eml includes selected attachments only when their registered bytes match the authorized local file. Mail-client draft import is untested.

After sending yourself, choose “I sent this manually”, the exact revision, actor and stated time. Record replies separately. These are user-reported outcomes, not delivery receipts. Review the feedback as evidence before changing a venture assessment. Automatic delivery is unavailable; a future provider needs exact-content approval, expiry, changed-content rejection and duplicate-send controls.

Local data and returning later

Your database and drafts persist on this computer. The default database is ~/.local/share/startup-foundry/foundry.local.db, independent of the launch folder. Configuration can select another store. Stop the console with Ctrl+C and restart it to return. Before migrations or bulk intake, make a fresh backup. Reports, questions and test limitations remain in the Foundry documentation and requests folders.

Developer commands
foundry storage info
foundry storage backup --output /absolute/new-backup.db
foundry ui --port 8765
foundry score import-original --sources-directory foundry/docs/sources
foundry idea list --disposition hold --blocker human_input
foundry existing-project intake --input checkpoint.json
foundry score assess --input assessment.json
foundry review append --input review.json
foundry input preview
foundry input handoff --id R006
foundry venture-score show --id v-sports-session
foundry proposal list
foundry workspace show --id v-coopain
foundry outreach export --id DRAFT_ID --format text --output draft.txt

FOUNDRY_DATABASE_URL selects storage; FOUNDRY_REQUESTS_DIR selects questions. FOUNDRY_ATTACHMENT_ROOTS contains approved local export directories, separated by the OS path separator. The default is the data directory's outreach-attachments. It grants no network delivery access.
