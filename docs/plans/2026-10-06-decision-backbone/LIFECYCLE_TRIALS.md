# Functional lifecycle replay protocol

Frozen before the replay on 2026-10-06. These trials exercise deterministic
coordination, not model quality, customer demand or token savings. Synthetic
observations are labelled and stored in new disposable databases.

| Family | Bounded scenario | Required outcome |
| --- | --- | --- |
| Discovery | Lunch-choice observations, then a changed observation | Known evidence remains available, new evidence is disclosed, a second task can be reviewed after restarting the CLI |
| Operating software | Account-boundary check fails | Hold only the release work; retain operating maturity and venture disposition |
| Suppliers | Capacity correction arrives after an agent result | Retain old findings, refuse stale effects, permit a fresh explicitly reconciled result |
| Changing direction | Edit a question/condition or narrow venture scope | Retain old map; dependent work needs explicit review; unrelated work remains usable |
| Competing sessions | Two results share one context; retry the winner | Exactly one set of effects; the other result needs reconciliation |
| Interrupted acceptance | Fail storage after evidence/decision creation | No partial evidence, decision, completion or head change |

Run the unit decision contracts, subprocess CLI lifecycle trial and real Chromium
workflow at 1280px and 390px. Screenshots are inspected; no horizontal overflow
or JavaScript errors are acceptable. Browser trial creates a conditional branch,
records a fact, expands context, previews and accepts a hold, then opens the
retained result in a fresh browser session.

The earlier agent-versus-file cost replay remains separate and unrun in this
implementation pass. A smaller context is not evidence of lower total token cost.
