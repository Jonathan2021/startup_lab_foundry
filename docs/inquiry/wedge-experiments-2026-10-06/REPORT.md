# Foundry wedge experiment conclusions

2026-10-06. The recommendation is to build a small **venture decision-maintenance
backbone for existing agents**, then evaluate one specialized source-change impact
executor. The [macro plan](../../plans/2026-10-06-decision-backbone/README.md) and
[first coding chunk](../../plans/2026-10-06-decision-backbone/CHUNK_1.md) are ready
for a subsequent implementation instruction. No application implementation ran.

## Evidence and decision

The user proposed two plausible advantages: reusable structure can reduce the
work a powerful agent must reconstruct, and a specialized trained small model
can provide some tasks at lower cost. This inquiry accepts both as engineering
hypotheses and narrows the next investment to an observable recurring workflow.

The [frozen protocol](PROTOCOL.md) preceded the synthetic runs. Eight fictional
cases covered local discovery, software operations, suppliers, outreach, pricing,
competition, fusion and a customer pivot. No invented evidence was placed in
the permanent Foundry store or the real Crous assessment.

| Probe | Observed result | Decision consequence |
|---|---|---|
| Context format and selection | 13,605 bytes for concise files; 22,288 for JSON packets; 22,437 for full dossiers. Packets miss one required unlinked fact. | Structure should live behind a concise agent view. Expose unclassified arrivals and incomplete coverage. Do not promise token savings from JSON. |
| Fresh-agent answers | Two isolated same-configuration agents recovered the four intended decisions from either format. | No clear small-sample format-quality advantage; test ongoing update work next. |
| Test-only transition mechanics | Ten frozen stale/duplicate/scope/unknown/stop/contradiction scenarios matched expected behavior. | Use these as acceptance requirements for a real implementation, not proof that one exists. |
| Current landscape | Close overlap from Vistaly, Productboard Spark, Beads and monitoring tools. | Graphs, memory, agents and semantic alerts alone are not the wedge. Compare actual change-handling workflows. |
| Specialization economics | A transparent sensitivity model works at some volumes/quality/cost assumptions and fails at others. | Measure whole-job cost and fallback rate before training or setting prices. |

The parent reran `experiments/run_experiment.py` and reproduced the reported
sizes, C03 missing source and ten expected transition results. A strong file
brief was given perfect relevance selection; the graph was given handcrafted
links. Neither maintenance cost was measured. Bytes/words are not billed tokens.
The cases are small and selected, so they do not establish how often the failures
occur, market demand, user savings, prediction accuracy or product superiority.

## Concrete next investment

One local loop: **resume current decision → retrieve sufficient context → work
with an existing agent → submit findings → review exact effects → preserve the
new state and affected next work**. The map connects that loop to the intended
outcome and conditional alternatives. Branches include stop/hold/unknown, and a
future alternative is not automatically a queued task.

New evidence can require re-review of an old decision without erasing its history
or stopping unrelated work. A late agent result can remain useful as evidence
while its old instructions are no longer applicable. This is the behavior the
first chunk should make reliable and easy to inspect.

The two prior intake flaws are included at the beginning: completion must allow
stop/hold and promotion must not duplicate an overlapping investigation. The
existing evidence, assessment, decision, work, artifact and review records are
reused. One small map head plus immutable typed revisions is proposed; no graph
database, model provider, hosted worker or plugin framework is required.

## What comes after that checkpoint

Fit one ordinary agent workflow, measure total reconstruction/upkeep against
competent files, and then test the narrow paid specialty: which decisions deserve
review after specified sources change? Use a prompted cheap model first and train
only if the measured task, quality gap and volume justify it. Synthetic examples,
independent critiques and held-out families are agent-owned work; the user is not
asked to create fixtures by hand.

Paid value can include managed continuity, collaboration, scheduled completion
and lower accepted-result cost. Users with effectively zero marginal cash
inference cost may buy convenience but cannot receive a positive cash saving
from a positive task fee. Keep BYO-agent use complete and portable.
