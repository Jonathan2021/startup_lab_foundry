# Foundry wedge experiments

Date: 2026-10-06. Frozen before the experiment runs. Scope: synthetic research,
read-only architecture inspection and a product/coding proposal. No application
implementation, live venture mutations, training, paid APIs, outreach or hosting.

## Hypotheses

H1: A task-specific context package can reduce the information an agent must
consume while retaining counterevidence, dependencies and decision conditions.
Compare against both a full organized file dossier and a strong concise file
brief. Do not attribute ordinary summarization gains uniquely to Foundry.

H2: Explicit decision dependencies and versioned result submission prevent
specific mistakes in scope, stale work, unsupported branch selection and duplicate
effects. A file workflow with equivalent code could also enforce these rules;
the proposed value is making them reusable and available without custom work.

H3: A narrowly specialized executor can cost less per accepted result than a
general agent. Investigate current primary-source support and a break-even
model. No trained-small-model quality, measured token saving, or profitability
claim without an actual corresponding run and known cost.

H4: A dynamic decision map helps connect current work to outcomes without turning
uncertain venture strategy into an automatically executable fixed workflow.
Exercise branching, unknown/inconclusive results, changes of objective,
contradictory evidence, shared resources and stop decisions.

## Cases and boundaries

Create eight explicitly synthetic venture cases spanning local service discovery,
software operations, physical supply, sales/outreach, pricing, competition,
venture fusion and strategic pivot. Use invented records and outcomes; any Crous
example is an illustration, not a new observation about the real restaurants.
Preserve current real records untouched. No historical-company claims without
their primary sources; invented cases are sufficient.

## Measurements and limitations

- Retain fixture inputs, generation scripts, required-fact oracle, outputs and
  hashes. Measure exact bytes/words; measure tokens only with an identified
  available tokenizer. Report serialization overhead and all selection rules.
- Test a full organized dossier, an oracle-curated concise Markdown brief and a
  deterministic dependency-selected package. Selection is synthetic and explicit;
  do not describe it as demonstrated semantic retrieval over arbitrary documents.
- Where session capacity permits, use fresh same-model agents on concise files
  versus structured packages without giving the answer key. Grade required facts,
  scope, next action, stop/hold behavior and unsupported claims. These tiny
  synthetic runs cannot establish provider/model cost or market demand.
- Record negative cases, omitted facts and cases where the strong file baseline
  matches or beats the proposed package. Do not tune cases after seeing results.
- Exercise deterministic acceptance rules with stale, duplicate, cross-scope,
  insufficient-evidence and contradictory-result submissions. Test-only scaffold
  is not a production feature and does not certify the existing application.
- Use explicit illustrative assumptions for financial sensitivity; separate
  customer comparison, serving margin and training amortization.

## Decision output

Choose one initial recurring job and integration path. Compare alternatives across
customer access, substitution, measurable advantage, implementation scope and
economic plausibility without pretending subjective ratings are measured facts.
Produce a dependency-ordered macro plan, a detailed first-chunk coding handoff,
stop/continue criteria, and a concrete branching example. Product direction can
be decisive while savings, quality and commercial demand remain testable claims.
