# R3: specialist-model factories, self-improving agent infrastructure and provider terms

Checked 2026-10-09 by pass R3 of session `fable-agentic-stack-20261009` (see
`../PROTOCOL.md`). I used only web sources and installed nothing. Labels: **vendor
claim** for vendor statements and **self-reported** for the authors' own results.
Star counts are what GitHub showed on 2026-10-09. Statements from the transcript are
treated as hypotheses.

**Coverage codes** (the AS02 capabilities):
- **a**: discovers specialization opportunities from heterogeneous logs.
- **b**: decides whether fine-tuning is worth it, versus optimizing prompts or skills.
- **c**: runs a local or open-weight specialist with fallback to a general model.
- **d**: tracks provenance and permitted use of training data.
- **e**: evaluates on held-out data, then rolls out in shadow or limited mode.
- **f**: retires or re-evaluates a specialist when the base model changes.

Values: Y = documented, P = partial, N = not documented on the cited pages, n/a = not applicable.

**Alternative paths (my reading, not legal advice):**
1. **Routing and outcome data.** Use task category, model, effort, test result, cost and latency to train a router or classifier. This fits OpenAI exception (a) if the model is not distributed, and Anthropic's permitted "categorization".
2. **Independent ground truth.** Tests, user-written fixes, permissively licensed data, or open-weight teachers, as Distil Labs uses ([FAQ](https://www.distillabs.ai/faq/)). The teacher's licence still applies.
3. **Environment rewards.** Use compilers, tests or verifiers. Whether a closed-model *judge* such as RULER with o3 is permitted is **UNVERIFIED**; a local judge or a programmatic verifier avoids the question.

None of the actors checked tracks permitted use for each training example.

## 3. What this means for AS02, AS09 and AS03

**Selling weight training is a contested and shrinking business.**
- In the last 16 months these consolidated or exited: OpenPipe's hosted platform, TensorZero, Humanloop, Predibase, Lamini and Fireworks' managed RFT.
- OpenAI is ending self-serve fine-tuning and cites "fewer use cases that require fine-tuning".
- At the same time, Distil Labs, Pioneer, Catalyst and Overmind all launched trace-to-specialist pipelines in 2026.

So AS02's upper rungs are crowded and commercially weak. Confidence: medium-high on the facts, medium on the interpretation.

**The lower rungs already ship as open source on the operator's own tools.** SkillOpt-Sleep mines recurring Claude Code and Codex tasks, optimizes skills, gates them on held-out tasks and proposes them to a human. Hermes, Letta, GEPA, DSPy and ACE cover nearby ground.

**Per capability:**
- **(a) Discovery.** Partly covered by Braintrust Topics, the SkillOpt-Sleep miner and Overmind. None of them estimates what specialization would return.
- **(b) "Discovers *when* fine-tuning is worthwhile".** None of the roughly 45 actors checked ships it. Products either assume the decision (Distil Labs, Pioneer, Catalyst), never escalate (SkillOpt-Sleep, Braintrust), or pick only the method (Anyscale).
  - The gap may exist because the answer is usually "no", which matches OpenAI's signal.
  - A volume-and-cost escalation rule is a feature that DSPy, SkillOpt or Catalyst could add, not obviously a company.

  Confidence it is uncovered: medium. Confidence it is a venture-scale wedge: low.
- **(c) Fallback to a general model.** Not shipped by any factory. It exists only as a manual pattern ([Stockton, 2026-03-02](https://mattstockton.com/2026/03/02/automating-the-path-from-frontier-models-to-fine-tuned-models.html)), and it overlaps AS01.
- **(d) Provenance and permitted use.** A real gap, made sharper by §2. Willingness to pay is unknown.
- **(f) Retirement when a newer general model wins.** Not found. Azure only retires fine-tuned models on a calendar ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/model-retirements), seen as a search result). Faster base-model gains make this more relevant.

**AS09.** Generic evaluations and skills are becoming commodities: Prime Intellect's public Environments Hub, Hermes community skills, and skill files that transfer across harnesses (self-reported). A library is defensible only with private, verified, domain-specific outcomes, and no evidence of that was found. AS09 is more likely a by-product of AS02 or AS04 (low confidence).

**AS03.** Re-optimizing when switching providers already exists: Not Diamond, recompiling with DSPy or GEPA, and SkillOpt's transfer. What remains is a per-user task profile and a trigger for recalibration.

**Cheapest honest first experiment: try to falsify AS02 with existing tools.**
- **E0, desk-only, about one day, metadata only.**
  - Inputs: the operator's Foundry records and the Claude Code and Codex transcripts for `startup_lab` and `kaggle/arc3`, covering 60 days.
  - Count clusters of homogeneous tasks. For each, record monthly volume, whether a programmatic verifier exists, success rate and token cost.
  - No outputs are used as training data.
  - **Pre-registered rule:** the weight rungs stay a candidate only if at least one cluster has ≥30 instances per month, has a verifier and has a stable specification. Otherwise, reduce AS02 to a "decision ledger" feature (escalation, provenance, retirement) on top of SkillOpt or DSPy.
- **E1, only if E0 passes and a human approves the install.**
  - Compare the baseline with off-the-shelf SkillOpt-Sleep or GEPA on a held-out split, and record the remaining gap.
  - Sleep can send transcript excerpts to the chosen provider, so check privacy first.
  - LoRA training stays deferred under ADR-0010.
  - Main falsifier: off-the-shelf skills close the gap.
