## 3. What this means for AS04

**Is the inner loop commoditized? Yes — high confidence.** A single-file MIT loop reached 97.6k stars and 13.6k forks within seven months ([repo](https://github.com/karpathy/autoresearch)). Tree/graph search with parallel branches is available as OSS (AIDE, evo, OpenEvolve, ShinkaEvolve, MLEvolve, CORAL) and as hosted services (Weco, AlphaEvolve GA, Gemini for Science, Autoscience, Kosmos). On MLE-bench at least five systems exceed 60% any-medal, and maintainers have paused submissions ([leaderboard](https://github.com/openai/mle-bench)). Building another inner loop has no defensible value.

**Are research memory and negative-result handling uncovered? Partly — medium-low confidence.** Within-run failure memory is now standard: MLEvolve labels every node success/failure and retrieves from it ([repo](https://github.com/InternScience/MLEvolve)); evo shares failure traces and discarded hypotheses ([repo](https://github.com/evo-hq/evo)); autoresearch logs discards and crashes ([program.md](https://github.com/karpathy/autoresearch/blob/master/program.md)); Kosmos keeps a structured world model ([Edison](https://edisonscientific.com/news/announcing-kosmos)). I found **no** system with all of these:
1. a typed, cross-project ledger (established / conjecture / counterexample / refuted / open question / failed approach) with provenance to runs;
2. noise-aware status, where an improvement inside measured rerun noise stays a conjecture. A 5-minute run moves val_bpb by about 0.03 ([autoresearch-mlx](https://github.com/trevin-creator/autoresearch-mlx)), and the base loop keeps any gain.
3. search-aware statistics, where the number of trials feeds the correction. Recent finance work argues that LLM strategy discovery must count trials (Deflated Sharpe/PBO) and must prevent leakage structurally, because deflation alone passed a leaky Sharpe-35 oracle ([arXiv 2608.27734](https://arxiv.org/pdf/2608.27734)). Reported LLM-agent alpha shrinks under reproduction ([arXiv 2605.16895](https://www.alphaxiv.org/abs/2605.16895)).

This is absence of evidence in a fast, long-tail field: a small fork may already do it ([awesome-autoresearch](https://github.com/alvinreal/awesome-autoresearch)).

**Is the outer loop uncovered? No — it is crowded at prototype level.** autocontext already promotes harness changes only after matched trials under a false-promotion budget, and adds model routing and distillation ([repo](https://github.com/greyhaven-ai/autocontext)). Sibyl writes reflection-derived prompt overlays ([repo](https://github.com/Sibyl-Research-Team/AutoResearch-SibylSystem)). ShinkaEvolve bandit-selects models within a run ([repo](https://github.com/SakanaAI/ShinkaEvolve)). GEPA and EvoAgentX optimise prompts and workflows ([GEPA](https://github.com/gepa-ai/gepa), [EvoAgentX](https://github.com/EvoAgentX/EvoAgentX)). What I did not find is a demonstration that such an outer loop raises *research* outcomes on held-out projects. That is an evaluation question, which makes it AS09 territory rather than AS04.

**Commercial reading (judgement):** hosted research agents are well funded (Edison $70M, Autoscience $14M, Weco $8M) or platform-owned (Google, Microsoft). A solo hosted "research OS" has no evident slot. The residual wedge is narrow, local and open: a **research ledger with negative results and trial-aware promotion rules**. It would sit under existing loops (autoresearch, evo, AIDE/Weco, W&B/MLflow MCP) and use Hindsight or Graphiti as storage. That suggests narrowing AS04 and merging its evaluation half with AS09; the math phase should not compete with Harmonic or Axiom on proving.

**Cheapest honest first experiment (no paid inference, no new accounts).** Use `/home/jonathan/kaggle/arc3`. It already holds 329 inquiry records under `docs/inquiry/` with frozen hypotheses, alternatives, "prior evidence consulted" sections and recorded negative closures; `PROGRESS.md` logs negative results (local listing, 2026-10-09).
- *H:* a typed ledger extracted from records up to date *t* surfaces relevant prior negative or counter-evidence for later hypotheses better than plain grep/BM25 over the same Markdown.
- *Design:* chronological split, for example records ≤ 2026-10-04 as memory and later records as probes. Gold labels are the earlier records each probe cites, plus blind-labelled missed negatives. Arms: (A) grep/BM25, (B) typed ledger, (C) optional Hindsight, already selected under ADR-0007.
- *Metrics:* recall@10 of cited prior evidence, missed-relevant-negative count, and extraction error rate on 30 sampled entries.
- *Stop rule:* if B beats A by fewer than 10 recall points and finds no missed negative in at least 90% of probes, do not build memory. Use an autoresearch-style `results.tsv` plus Markdown instead.
- *Only on pass:* run a prospective A/B with an existing loop (evo or an autoresearch skill under current subscriptions) on a deterministic arc3 subset metric. Measure the rerun noise floor with at least 3 seeds first. Defer the outer loop until memory shows value.
