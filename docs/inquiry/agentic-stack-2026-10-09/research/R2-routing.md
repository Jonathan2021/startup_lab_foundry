## 2. Claim verification

1. **TensorZero repository archived on 2026-06-12: CONFIRMED.** The GitHub page reads "archived by the owner on Jun 12, 2026" ([GitHub](https://github.com/tensorzero/tensorzero), checked 2026-10-09). The co-founder said the company is winding down, spent less than half of $7.3M, and will not maintain the Apache-2.0 code ([HN](https://news.ycombinator.com/item?id=48518120)).
2. **Mastra introduced ModelSelectionProcessor in September 2026, with classifier-based selection and fallbacks: CONFIRMED.** It shipped in `@mastra/core` 1.70.0, released 2026-09-24 ([release](https://github.com/mastra-ai/mastra/releases/tag/%40mastra/core%401.70.0)). The selection runs through an evaluation-model classifier ("choices") or a custom classifier. If the classifier errors, it falls back to the configured model. If the selected model fails, the agent's fallback models take over ([docs](https://mastra.ai/reference/processors/model-selection-processor)). It does **not** learn from outcomes.
3. **RouteLLM status: DORMANT (not archived).** The repository has no archive banner and shows 5.6k stars ([GitHub](https://github.com/lm-sys/RouteLLM)). The last commit was 2024-08-10 ([commits](https://github.com/lm-sys/RouteLLM/commits/main)). No official deprecation was found (UNVERIFIED).
4. **"No mainstream gateway learns routing from downstream task outcomes": PARTLY REFUTED.**
   - LiteLLM Auto Router v2 ships Thompson pools fed by "reward feedback", signal undocumented ([blog](https://docs.litellm.ai/blog/autorouter-v2)); its Heuristic v2 is pretrained, non-adaptive ([blog](https://docs.litellm.ai/blog/heuristic-v2)).
   - Not Diamond Code claims real-time adaptation to implicit developer feedback (vendor claim, early access).
   - OpenRouter, Azure, Bedrock and Vertex use offline training or aggregate data; Bedrock says it cannot adapt to application-specific data (§1).
   - vLLM SR's outcome gate is off by default; TensorZero is archived.
   - **No gateway found documents test pass/fail, review acceptance or escalation as routing reward** (absence finding, UNVERIFIED).
5. **Claude Code built-in fallback ignores usage limits: CONFIRMED.** "Authentication, billing, rate-limit … errors … never trigger a switch" ([docs](https://code.claude.com/docs/en/model-config)).
6. **Subscription auth for third-party tools (relevant to H2): MIXED.**
   - Anthropic help page (updated 2026-10-07): Agent SDK, `claude -p` and third-party apps can still use subscription limits; Max/Team plans now include monthly API credits ([support](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)).
   - Claude Code legal page: third-party developers may not "route requests through Free, Pro, or Max plan credentials on behalf of their users" or "intermediate Claude.ai credentials or session tokens"; a user signing in to the *unmodified* binary is allowed ([legal](https://code.claude.com/docs/en/legal-and-compliance), undated, read 2026-10-09).
   - OpenAI "Sign in with ChatGPT" (2026-09-29) lets partner tools draw plan allowance, limited trial (secondary: [The New Stack](https://thenewstack.io/sign-in-with-chatgpt/), [eesel](https://www.eesel.ai/blog/sign-in-with-chatgpt)).

## 3. What this means for AS01 / AS03 / AS08

**Basic routing is commoditized (high confidence).** Fallbacks, retries, load balancing
and budgets are standard in every gateway above. Classifier or complexity routing is
free or bundled in LiteLLM OSS, Mastra, OpenRouter (no router fee), Azure, Bedrock,
Vertex, Cursor, Copilot, Augment and Factory. The category is consolidating:
Stripe agreed to buy OpenRouter, Palo Alto Networks bought Portkey and Mintlify bought
Helicone. Martian and Unify appear to have moved away from routing, and TensorZero shut
down citing commercial fit. A standalone "smart router" is not a viable wedge.

**AS01: narrow, and expect overlap (medium confidence).** Two actors now claim its core:
- Not Diamond Code: model plus effort per step for Claude Code, learning from developer
  feedback (vendor claim, early access).
- LiteLLM Auto Router v2: effort ladders, bandit pools and stall escalation, open source.

What still looks uncovered, judged on documentation only:
- (i) Reward taken from **machine-verifiable task outcomes at the orchestrator level**
  (tests passed, review accepted, human escalation), keyed by *task category* rather
  than prompt text.
- (ii) An explicit escalate-fast/downgrade-slowly policy with logged regret and evidence.
- (iii) Optimising against **subscription quota** rather than dollars, with vendor CLIs
  as the arms.

Uncertainty: LiteLLM's reward API may already accept arbitrary rewards, and a short check
of its code would settle this. Not Diamond's implicit signals may include test results.
As a product, AS01 competes with funded and open-source actors. As a thin open-source
policy and evidence layer inside an orchestrator, it is a defensible experiment with weak
monetisation. Consider merging it into AS08 or AS09.

**AS03: partially covered, gap at the harness level (low–medium confidence).**
- Not Diamond Prompt Optimization rewrites prompts per model.
- vLLM SR checks provider-state portability for mid-session switches.
- Azure advises re-evaluating after routing changes.

Nothing found calibrates **whole agent-harness configurations** across a switch
(e.g. Codex CLI to Claude Code, including instruction files, skills and effort defaults)
or detects negative transfer per task profile. Eval-platform overlap is for R3/R5 to
assess. For now, treat AS03 as a feature of AS09.

**AS08: strong demand signal, narrow legitimate space (medium confidence).** Quota-aware
failover across subscriptions already exists: OmniRoute (74.5k stars), CLIProxyAPI
(54.6k), Quotio and 9Router. Stars show attention, though they can be inflated. These
tools work by proxying or pooling OAuth tokens, which Anthropic's legal page prohibits
for third-party developers.

The legitimate options leave gaps:
- Claude Code's own fallback ignores rate limits.
- OpenCode has no native cross-model fallback.
- Account switchers stay within one provider.
- amux is manual.

**The uncovered, terms-respecting form is a local supervisor.** It would run the
*unmodified* official CLIs under each user's own sign-in. It would read local quota
signals (ccusage-style data, the statusline, usage-limit messages), write a durable task
checkpoint (worktree plus handoff note), and resume in another CLI or a local model
behind circuit breakers.

Risks:
- Anthropic says advertised limits assume "ordinary, individual usage" ([legal](https://code.claude.com/docs/en/legal-and-compliance)).
- Codex automation terms were not checked.
- Max API credits and Sign in with ChatGPT may shift the economics.
- Monetisation looks like an open-source tool for power users.

**Outcome-learned routing for CLI agent fleets** appears uncovered only at the
intersection of three properties, each covered separately by someone:
- fleet or orchestrator scope,
- task-level verifiable rewards,
- quota as the binding constraint across vendor CLIs.

This rests on absence of evidence on 2026-10-09 and should be rechecked before any build.
